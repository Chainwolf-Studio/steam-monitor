## 8. Red Dust Colony

- **AppID:** 2536140
- **Title:** Devlog #19 - 3D Gameplay
- **Published:** 2026-09-24T22:38:21Z
- **Author:** (not provided)
- **URL:** https://store.steampowered.com/news/app/2536140/view/678509959027098923
- **GID:** 678509959027098923

### Announcement text

Hello and welcome to the 19th devlog. This time around there's one change that touches pretty much everything.
Brief history
I'm not sure I've ever mentioned this here, but around 6 years ago when this project started, it was meant to be much smaller in scope, which is partly why it started as a completely 2D game. It turns out I still have the first ever prototype graphics I made for it: 
The graphics quickly changed to 3D since that better matched our skills, but the gameplay remained on a 2D plane. In fact, up until right before the first ever build shared with anyone, the terrain itself didn't even have any real elevation.
(yes, the interface used to be pixel art)
This didn't look good, so the terrain that's currently in the demo was implemented. With the gameplay still on the 2D plane though, there wasn't any way to climb the terrain or see through it, so mining was changed to just completely flatten the terrain instead of digging any tunnels. I'd only ever considered this to be a temporary solution as it was becoming clear that the gameplay also needed to be 3D. Since then, all new work has been done with this in mind but a huge chunk of the game still had no concept of above and below.
The in-progress update touches on mining and introduces prospecting (more on this next time), both of which depend on whether the game is 2D or 3D. So, the question was: do I make it rely on the old 2D code and dig the hole a little deeper or bite the bullet and transition everything to 3D? Given the title of the devlog, it should come as no surprise that I chose the latter.
Optimization
Currently, the maximum map size is 400x400 tiles. Bigger than most colonies will ever need, but not outrageously big. That means there are 160,000 cells on the 2D plane. With the game going 3D, this is further multiplied by the current limit of 48 levels. This means instead of having a maximum of 160k cells to deal with, now we have 7.6M. Higher-end PCs could do this without much trouble, but the goal with this game is for it to work comfortably on lower-end PCs too.
As you can probably already tell, a lot of those cells are either air or terrain that's buried deep within, never to be easily seen. This makes it easy to "compress" the information and dramatically reduce memory usage. In fact, after this change, the game uses less memory than before even though the maps are much bigger. It even makes save files about 30% smaller.
Navigation
Making colonists walk on different height plateaus was straightforward, if a bit time-consuming, but this feature isn't really useful if they also can't walk between the different heights, so now we have stairs and ladders. Models and animations still need to be done, but the logic part of it is working fine.
Tunnels
With the terrain no longer collapsing and being flattened when mining, tunnels are now possible. This does mean that colonists can work deep under the mountains, so a way to see through the terrain was needed. 
There's no support for building inside mountains without using hull yet, but this is definitely under consideration now. Playing as dwarves on Mars could be really cool.
New map generation
The previous map generators all worked with the 2D gameplay assumption, leaving large sections of the terrain at height 0 so the players can expand, but now the players need to be able to go up as well as down, so all generators needed a fresh update.
The next update is still expected to land in October. In the next devlog I'll go into more detail on how updates and patches will work going forward.
Demo-wise, you can also expect a new patch to drop in a few days with some food-related improvements, some QoL features and a bunch of bug fixes. Notably, the pause sound is also going to change because we've had some feedback notes about it sounding too much like an error sound.
That's all for today.
See you next time!

## 19. Spirit of Europe - Enlightenment

- **AppID:** 4642020
- **Title:** Devlog 10 - Flashback
- **Published:** 2026-09-21T06:30:08Z
- **Author:** (not provided)
- **URL:** https://store.steampowered.com/news/app/4642020/view/670623586021542488
- **GID:** 670623586021542488

### Announcement text

At this point, the game had enough moving parts that it needed proper long-term progression, not just local interactions and isolated unlocks. So it was time to finish up the projects tree.
The projects tree is like your usual tech tree in most strategy games. Our has a twist though: historical personalities produce works through inspiration - which is a currency produced by your cities and various developments. These works coagulate into projects - which are whole fields like “celestial mechanics”, “steam power” or “chamber music”.
This setup, coupled with the fact that the player doesn’t have enough time to complete the whole tree and/or conquer all of Europe make replayability attractive. Maybe on this playthrough you wanted to go more into science - so, unlike other games where “you just invest into that part of the tree”, here, you also need to expand to the cities that hold the personalities required by that section of the tree.
In order to glue all of this together, we had to make lots of adjustments and tests to make sure that at least some of the paths are straightforward - for players who are not in the mood for weird detours just to complete one branch.
This also meant another round of tightening the data. Because a progression system like this can’t have any bloat or it will break. Which obviously meant cutting some more while also sacrificing some art that was already made for things that won’t be making the final cut.
Why cut? Because the tree was already bordering “scary”, and we know how quite a few players generally react when they see Path of Exile’s infamous skill tree. Spoiler alert: it’s Alt+F4. And while we love POE, we are aware of the fact that it’s either an acquired taste or a niche one.
So this phase became a lot more than “click here to insert projects tree”, because we needed to make sure it actually works within the game context.
While at it, we also added the “real” art for the project tree, elaborate frames and various other UI elements, as well as precisely 2.65 buckets of icons. We also implemented some material effects and that was that! We finally had the whole game assembled!
Oh wait… The 3D art…

### Announcement text

Hello alchemists and apprentices!  
We wanted to dive a bit into what motivated the creation of Potions Galore. The whole game revolves around one idea, that acted as our guiding light: “What if you actually were in an Alchemist’s house-shop, and you’d have all these potions that someone worked hard to make, and you’d be able to read about them in an exhaustive tome?”
So that’s what we did. We created a tome that is populated as you pick up new potions. If the title is not explanatory enough to guide the placement, you can open up the tome and read the entry description to get more clues. And sometimes, their lore, for giggles.
100% Human made
We know there is a lot of talk around AI usage, not only in games but in every creative industry and beyond. As such, we wanted to make our stance as clear as possible:

So we started implementing developments first, then policies, then actions, along with all the usual lovely baggage: requirements, costs, outputs, modifiers, limits, effects, edge cases, and the eternal question of whether a system is genuinely interesting, or whether it only looks that way because it’s, well… yours.
Naturally, this also meant another round of revisions. Because the moment these systems became clickable, every stubbornly lingering vague design assumption became a practical problem. Costs had to make sense, effects had to be traceable, dependencies had to behave, and the whole thing had to be readable enough that the player could tell what was going on. Of course, because we want the player to be comfortable, we just added detailed tooltips for every single thing you hover on… Ok, we’ll be honest: we did it so we can more easily spot bugs.
This was also the point where the game loop began to show itself clearly enough that it started feeling like an actual strategy game.
And, obviously, the moment that happened, everything became both more interesting and more difficult, because it quickly became obvious just how much balancing this game was going to need, especially since this particular design relies to a great extent merely on good ‘ol numbers.
(April 2026)
